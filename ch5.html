1) Cloud Computing Layers

Cloud computing is organized in four layers, from the physical machines at the bottom up to the applications at the top.

Hardware Layer

Manages the physical resources of the cloud: physical servers, routers, switches, power and cooling systems. Implemented in data centers, which contain thousands of servers organized in racks and connected through switches, routers or other fabrics. Typical issues: hardware configuration, fault tolerance, traffic management, power and cooling resource management. (CPU, memory, disk, bandwidth)

Infrastructure Layer (IaaS)

Also called the virtualization layer. Creates a pool of storage and computing resources by partitioning the physical resources using virtualization technologies such as VMware. Essential because key features like dynamic resource assignment are only available through virtualization. (Computation VM, block storage)

Platform Layer (PaaS)

Built on top of the infrastructure layer; consists of operating systems and application frameworks. Its purpose is to minimize the load of deploying applications directly into VM containers. Example: Google App Engine. (Software framework Java/.NET, storage DB/file)

Application Layer (SaaS)

The actual cloud applications. Unlike traditional applications, they can leverage automatic scaling to achieve better performance, availability and lower operating cost. (Business applications, web services, multimedia)

1) طبقات الحوسبة السحابية

الحوسبة السحابية مقسمة إلى أربع طبقات، من الأجهزة الفيزيائية بالأسفل إلى التطبيقات بالأعلى.

طبقة العتاد (Hardware)

تدير الموارد الفيزيائية للسحابة: سيرفرات، راوترات، سويتشات، أنظمة الطاقة والتبريد. تُنفَّذ في مراكز البيانات التي تحوي آلاف السيرفرات المنظمة في racks والمتصلة بسويتشات وراوترات. المشاكل الشائعة: إعداد العتاد، تحمل الأعطال، إدارة الترافيك، إدارة الطاقة والتبريد. (CPU، ذاكرة، قرص، bandwidth)

طبقة البنية التحتية (IaaS)

تُسمّى أيضاً طبقة الـ virtualization. تنشئ مجمّعاً (pool) من موارد التخزين والحوسبة عبر تقسيم الموارد الفيزيائية بتقنيات مثل VMware. أساسية لأن ميزات مثل التخصيص الديناميكي للموارد لا تتوفر إلا بالـ virtualization. (أجهزة افتراضية، تخزين block)

طبقة المنصة (PaaS)

مبنية فوق طبقة البنية التحتية؛ تتكون من أنظمة تشغيل وأطر عمل للتطبيقات (frameworks). هدفها تقليل عبء نشر التطبيقات مباشرة داخل حاويات الـ VM. مثال: Google App Engine. (إطار برمجي Java/.NET، تخزين DB/ملفات)

طبقة التطبيقات (SaaS)

التطبيقات السحابية الفعلية. بعكس التطبيقات التقليدية، تستفيد من التوسع التلقائي لتحقيق أداء وتوفر أفضل وتكلفة تشغيل أقل. (تطبيقات أعمال، web services، وسائط)

2) What is PaaS & How Does It Work?

Platform as a Service (PaaS) is a cloud computing model providing developers with a platform to build, deploy and manage applications without worrying about the underlying infrastructure.
Analogy: the best-known software platforms for desktop software are Microsoft Windows and Mac OS. PaaS is the same idea in the cloud: a ready platform you build your applications on.

Who manages what?

LayerOn-premiseIaaSPaaSSaaS
Applications, DataYouYouYouVendor
Runtime, Middleware, OSYouYouVendorVendor
Virtualization, Servers, Storage, NetworkingYouVendorVendorVendor

How PaaS works

PaaS solutions are specific to application and software development and typically include:

Cloud infrastructure

Data centers, storage, network equipment and servers.

Middleware software

Operating systems, frameworks, development kits (SDK), libraries and more.

User interface

A graphical user interface (GUI), a command line interface (CLI) and an API interface.

2) ما هي PaaS وكيف تعمل؟

PaaS (المنصة كخدمة) نموذج حوسبة سحابية يوفر للمطورين منصة لبناء ونشر وإدارة التطبيقات دون الانشغال بالبنية التحتية الأساسية.
تشبيه: أشهر منصات برمجيات سطح المكتب هي Microsoft Windows وMac OS. الـ PaaS نفس الفكرة بالسحابة: منصة جاهزة تبني عليها تطبيقاتك.

كيف تعمل PaaS

حلول PaaS مخصصة لتطوير التطبيقات والبرمجيات وتتضمن عادةً:

البنية التحتية السحابية

مراكز بيانات، تخزين، معدات شبكة، وسيرفرات.

برمجيات Middleware

أنظمة تشغيل، frameworks، أدوات تطوير (SDK)، مكتبات وغيرها.

واجهة المستخدم

واجهة رسومية (GUI)، وواجهة سطر أوامر (CLI)، وواجهة API.

3) Key Benefits of PaaS

Cost efficiency

Pay only for what you use.

Low maintenance

The provider maintains the platform.

Scalability

Automatic scaling based on demand.

Faster time-to-market

Pre-configured environments speed up development.

Focus on development

No need to manage servers or runtime.

3) أهم فوائد PaaS

كفاءة التكلفة

5) Challenges of PaaS

  • Vendor lock-in: limited portability between providers.
  • Customization limits: you work within what the platform allows.
  • Dependency on provider: your application relies on the provider’s platform and availability.

5) تحديات PaaS

  • Vendor lock-in: قابلية نقل محدودة بين المزودين.
  • حدود التخصيص: تعمل ضمن ما تسمح به المنصة.
  • الاعتماد على المزود: تطبيقك يعتمد على منصة المزود وتوفرها.
