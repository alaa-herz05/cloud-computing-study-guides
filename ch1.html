2) What is Cloud Computing?

Cloud computing is a general term for a new class of network-based computing that takes place over the Internet. It is a technology that uses remote servers on the internet to store, manage, and access data online rather than on local drives. The data can be anything: files, images, documents, audio, video, and more.

The NIST definition

Cloud computing is a model for enabling convenient, on-demand network access to a shared pool of configurable computing resources (e.g., networks, servers, storage, applications, and services) that can be rapidly provisioned and released with minimal management effort.
  • It provides a high level of abstraction of the computation and storage model: the user does not see the hardware details.
  • It has essential characteristics, service models, and deployment models.

In the slide’s picture, the cloud sits in the middle and connects mobile, laptop, server, desktop, storage, applications, database and network, with Private, Public and Hybrid clouds below it.

Example: Instead of keeping your photos on a flash drive, you upload them to Google Photos or iCloud. They are stored on the company’s servers and you can open them from any device with internet.

What cloud computing provides

  • Shared services instead of local servers or storage resources.
  • Access to information from most web-enabled hardware.
  • Cost savings: reduced facility, hardware/software investment and support.

2) ما هي الحوسبة السحابية؟ What is Cloud Computing?

الحوسبة السحابية مصطلح عام يصف نوعاً جديداً من الحوسبة المعتمدة على الشبكة، تتم عبر الإنترنت. هي تقنية تستخدم سيرفرات بعيدة (Remote Servers) على الإنترنت لتخزين البيانات وإدارتها والوصول إليها أونلاين بدل الأقراص المحلية. والبيانات ممكن تكون ملفات، صور، مستندات، صوت، فيديو وغيرها. Cloud Computing is a general term used to describe a new class of network-based computing that takes place over the Internet. It uses remote servers on the internet to store, manage, and access data online rather than local drives.

تعريف ثاني (NIST)

الحوسبة السحابية نموذج يتيح وصولاً مريحاً وعند الطلب عبر الشبكة إلى مجموعة مشتركة من الموارد الحاسوبية القابلة للضبط (شبكات، سيرفرات، تخزين، تطبيقات، خدمات)، ويمكن توفيرها وتحريرها بسرعة وبأقل جهد إدارة. A model for enabling convenient, on-demand network access to a shared pool of configurable computing resources (networks, servers, storage, applications, services) that can be rapidly provisioned and released with minimal management effort.
  • توفر مستوى عالٍ من التجريد (high level abstraction) لنموذج الحوسبة والتخزين: المستخدم ما يشوف تفاصيل الأجهزة.
  • لها: خصائص أساسية + نماذج خدمة + نماذج نشر.

شكل الشريحة: السحابة في المنتصف وحولها Mobile, Laptop, Server, Desktop, Storage, Applications, Database, Network وغيرها، وتحتها أنواعها: Private cloud, Public cloud, Hybrid cloud. أي أنها تربط كل الأجهزة والخدمات عبر الإنترنت.

مثال: بدل ما تخزن صورك على فلاشة أو قرص جهازك، ترفعها على Google Photos أو iCloud. الصور مخزنة على سيرفرات الشركة وتفتحها من أي جهاز عنده إنترنت.

ماذا توفر لنا؟ What cloud computing provides

  • خدمات مشتركة بدل السيرفرات أو التخزين المحلي (Shared services).
  • الوصول للمعلومات من أغلب الأجهزة المتصلة بالويب.
  • توفير بالتكلفة: تقليل الاستثمار في المرافق والأجهزة/البرمجيات والدعم (Cost savings).

3) Cloud Computing Architecture

The architecture is divided into two parts:

Front End

Used by the client. It contains the client-side interfaces and applications needed to access cloud platforms: web browsers (Chrome, Firefox, Internet Explorer), thin and thick clients, tablets and mobile devices.

Back End

Used by the service provider. It manages all the resources needed to provide cloud services: huge data storage, security mechanisms, virtual machines, deployment models, servers, traffic-control mechanisms, etc.

Architecture layers (from the diagram)

PartLayers
Front EndClient Infrastructure, then the Internet
Back EndTop to bottom: Application, Service, Cloud Runtime, Storage, Infrastructure, surrounded by Management and Security

Another diagram shows the flow: end-user devices (mobile, laptop, printer, desktops), then switch/router, then the Internet, then the cloud (servers, virtual desktop, software platform, application, storage data). A third diagram splits the cloud into three layers: Application (monitoring, content, collaboration, communication, finance), Platform (identity, runtime, queue, database, object storage) and Infrastructure (compute, block storage, network).

Components of the architecture

  • 1. Client Infrastructure: a front-end component that provides a GUI (Graphical User Interface) to interact with the cloud.
  • 2. Application: any software or platform that a client wants to access.
  • 3. Service: manages which type of service you access according to the client’s requirement.
Example: You open Google Docs in Chrome. Chrome = front end (client infrastructure), Google Docs = application, and Google’s servers that store and process the file = back end.

4) Operations & SLA

Cloud computing operations

  • Developing new applications and services
  • Storage, backup, and recovery of data
  • Hosting blogs and websites
  • Delivery of software on demand
  • Analysis of data
  • Streaming videos and audios

Service Level Agreement (SLA)

An SLA is a contract between a network service provider and a customer that specifies, usually in measurable terms (QoS), what services the provider will furnish.

Common contents of the contract:

  • Performance guarantee metrics
  • Up-time and down-time ratio
  • System throughput
  • Response time
  • Problem management details
  • Penalties for non-performance
  • Documented security capabilities
Example: The provider guarantees 99.9% uptime; if the service falls below that, the customer gets a discount (penalty).

Some commercial cloud providers

Logos on the slide include: Amazon Web Services, Microsoft Azure, Salesforce, Oracle Marketing Cloud, Zoho CRM, Microsoft Dynamics, Joyent, Engine Yard, GoGrid, Verio, Bitrix24, Insightly, SuperOffice, Mosso, 3tera, Sun and others.

5) Essential Characteristics

On-Demand Self Service

A consumer can unilaterally provision computing capabilities (server time, network storage, number of servers) automatically, without human interaction with each service provider.

Heterogeneous (Broad) Access

Capabilities are available over the network and accessed through standard mechanisms that support heterogeneous thin or thick client platforms. A thin client is web-based with most processing on the server; a thick client is installed on the client side and does most processing locally.

Resource Pooling

The provider’s resources are pooled to serve multiple consumers using a multi-tenant model. Physical and virtual resources are dynamically assigned and reassigned according to consumer demand.

Measured Service

Cloud systems automatically control and optimize resource use through a metering capability. This gives an analyzable and predictable computing platform.
Examples: On-demand: you create a server with one click, with no call to anyone. Pooling: several companies share one physical server without seeing each other’s data. Measured: you pay only for the hours or gigabytes you used.

Where is my data?

  • Data resides on servers that the customer cannot physically access.
  • Vendors may store data anywhere at the lowest cost if not restrained by agreement, which is why the SLA matters.

5) الخصائص الأساسية Essential Characteristics

On-Demand Self Service

المستخدم يوفر قدرات الحوسبة (وقت السيرفر، تخزين الشبكة، عدد السيرفرات) تلقائياً وبمفرده بدون تدخل بشري من المزود.

Heterogeneous (Broad) Access

القدرات متاحة عبر الشبكة بآليات قياسية تدعم منصات عميل متنوعة thin أو thick.

Resource Pooling

موارد المزود تُجمّع لخدمة عدة مستهلكين بنموذج Multi-tenant، وتُوزَّع وتُعاد توزيعها ديناميكياً (فيزيائية وافتراضية) حسب الطلب.

Measured Service

النظام يتحكم تلقائياً ويحسّن الموارد باستخدام قدرة قياس (Metering)، فيوفر منصة قابلة للتحليل والتنبؤ.
أمثلة: On-demand: تنشئ سيرفراً بضغطة زر بدون اتصال بأحد · Pooling: عدة شركات تشارك نفس السيرفر المادي بدون ما ترى بيانات بعض · Measured: تدفع حسب الساعات أو الغيغابايتات التي استخدمتها فقط.

أين بياناتي؟ Where Is My Data?

  • البيانات موجودة على سيرفرات لا يستطيع العميل الوصول إليها فيزيائياً.
  • الموردون ممكن يخزنون البيانات في أي مكان بأقل تكلفة إذا ما قيّدهم الاتفاق، لذلك أهمية الـ SLA.

6) On-Premise vs Off-Premise

On-premise software is installed on local servers or computers, while off-premise software is hosted on remote servers or in the cloud. On-premise deployment requires the organization to purchase, install, and maintain the hardware and software infrastructure. (“Premises” means the building: on = inside it, off = outside it.)

FeatureOn-PremisesOff-Premises (Cloud)
LocationPhysically inside your company’s buildingHosted remotely in a provider’s data center
Cost structureHigh upfront capital expense (CapEx) for hardwarePredictable monthly/annual subscription (OpEx)
Control & securityFull ownership of data, hardware and configurationsShared responsibility; physical security managed by the vendor
MaintenanceHandled entirely by your in-house IT teamManaged, updated and maintained by the provider
ScalabilitySlow and expensive (buy new servers)Instant and flexible (scale resources up or down online)
ReliabilityVulnerable to local power outages and disastersHigh uptime backed by global redundancy networks

7) Cloud Deployment Models

Private Cloud

Operated solely for one organization. It may be managed by the organization or a third party and may exist on-premise or off-premise.

Community Cloud

Shared by several organizations and supports a specific community with shared concerns. May be managed by the organizations or a third party, on-premise or off-premise.

Public Cloud

Made available to the general public or a large industry group, and owned by an organization selling cloud services.

Hybrid Cloud

A composition of two or more clouds (private, community or public) that enables data and application portability.
Examples: Private: a bank’s cloud inside its own data center. Community: several universities sharing a research cloud. Public: AWS / Azure. Hybrid: a company keeps sensitive data on a private cloud and runs its website on a public cloud.

7) نماذج النشر Cloud Deployment Models

Private Cloud

مُشغَّلة لمؤسسة واحدة فقط. تديرها المؤسسة أو طرف ثالث، وقد تكون on-premise أو off-premise.

Community Cloud

البنية مشتركة بين عدة مؤسسات تدعم مجتمعاً له اهتمامات مشتركة. تديرها المؤسسات أو طرف ثالث، on/off premise.

Public Cloud

متاحة للعامة أو لمجموعة صناعية كبيرة، وتملكها منظمة تبيع الخدمات السحابية.

Hybrid Cloud

مزيج من سحابتين أو أكثر (private, community, public) يتيح قابلية نقل البيانات والتطبيقات (portability).
أمثلة: Private: سحابة بنك داخل مركز بياناته · Community: عدة جامعات تتشارك سحابة بحثية · Public: AWS / Azure · Hybrid: شركة تحتفظ بالبيانات الحساسة على private وتشغّل موقعها على public.

8) Service Models & Advantages

The “Types of Cloud Computing” slide splits the cloud by deployment (Private, Public, Hybrid) and by service model (IaaS, PaaS, SaaS). Note: the lecture file does not explain the three service models in detail, so this is a basic summary:

IaaS

Infrastructure as a Service: servers, storage and networks, e.g. AWS EC2.

PaaS

Platform as a Service: a platform to build and deploy apps without managing infrastructure, e.g. Google App Engine.

SaaS

Software as a Service: ready-made software through the browser, e.g. Google Docs, Salesforce.
Advantages: cost savings, access from any device, instant scaling, provider-managed maintenance, high reliability.

الشريحة (Types of Cloud Computing) تقسم السحابة إلى: حسب النشر (Private, Public, Hybrid) وحسب نموذج الخدمة (IaaS, PaaS, SaaS). ملاحظة: ملف المحاضرة لا يشرح النماذج الثلاثة بالتفصيل، فهذا ملخص أساسي لتكون جاهز:
